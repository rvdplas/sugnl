# Contributing to SUGNL

Thanks for considering contributing to the SUGNL website! ❤️

SUGNL is a community for the Sitecore community, by the Sitecore community. The same applies to this website.

The website is open source because we want everyone to be able to contribute. Whether you want to fix a typo, add community content, improve accessibility, squash a bug, improve the design, or build something completely new, contributions are welcome.

**The more people that get involved, the better the website and the community become.**

## Ways you can contribute

You don't need to make a large code contribution. There are plenty of ways to help:

* Fix typos or improve existing content
* Add or update community information
* Add community blog sources
* Improve accessibility
* Improve the user experience or design
* Fix bugs
* Improve performance
* Suggest new features
* Improve documentation
* Help with event-related content
* Review or test someone else's pull request

Have another idea? Great. Feel free to suggest it.

## Before you start

For small changes, feel free to create a pull request directly.

For larger changes or new features, consider opening an issue first so we can discuss the idea together. This helps prevent spending a lot of time on something that might conflict with other work or plans for the website.

That said, we don't want process to get in the way of contributions. If you've built something useful, send us a pull request and we'll take a look.

## Pull requests

When creating a pull request:

* Give it a clear title
* Briefly explain what you changed and why
* Include screenshots for visual changes where useful
* Keep the pull request focused where reasonably possible
* Make sure your changes work as expected

Don't worry about making everything perfect before opening a pull request. Feedback and collaboration are part of the process.

Draft pull requests are welcome too.

## Code and design

There isn't an extensive set of coding rules.

Try to:

* Follow the style of the existing code
* Keep solutions as simple as possible
* Prefer readable code over clever code
* Keep the website fast and lightweight
* Consider mobile users
* Consider accessibility
* Avoid introducing dependencies unless they provide clear value

If something can be improved during review, we'll work it out together.

## Community first

Above all, remember that SUGNL is a community project.

Be respectful, constructive and welcoming when discussing ideas, reviewing contributions or giving feedback.

You don't need to be a SUGNL organiser, Sitecore MVP, or expert developer to contribute. If you see something that could be better, you're invited to help improve it.

Questions, ideas and contributions are always welcome.

Thanks for helping make SUGNL better! ❤️
